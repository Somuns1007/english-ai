## 3. 页面状态机实际实现

实际实现的 7 个阶段(前后端一致, 阶段由服务端事件流推导, 刷新安全):

```
intro → option_preview(可跳过) → first_pass → check_round_1
      → blind_full_replay(3/3 时跳过) → check_round_2(仅错题) → result_final
```

- 阶段推导: `derive_stage()` 从 cp_events 全量事件流 + cp_responses 推导, 前端不持有权威状态, 刷新后从 `GET /sessions/{sid}` 恢复。
- 本 Pilot 全程**不存在**: transcript reveal、答案区间、句子级 clip、当前答案位置提示、second pass 前的 correct answer 泄露; 无 Sentence Lab / Review / Profile 功能混入。

## 6. observation / event schema (cp_events)

| 字段 | 类型 |
|---|---|
| id / session_id / student_id | TEXT |
| event_type | TEXT(白名单) |
| payload | TEXT(JSON, 白名单字段, `_assert_cp_clean` 强制) |
| client_at / server_at | TEXT |

事件白名单: `cp_preview_open / cp_preview_skip / cp_preview_mark / cp_pass_start / cp_pass_progress / cp_pass_end / cp_pass_interrupted / cp_replay_start / cp_replay_progress / cp_replay_end / cp_replay_interrupted / cp_round1_submit / cp_round2_submit / cp_session_summary`。

- 未知 event_type 直接丢弃(测试 `test_unknown_events_dropped` 覆盖)。
- payload 禁词: `attention / working_memory / processing_speed` 等能力推断词一律拒绝。
- 事件中**不含**答案、对错、transcript、时间定位。

## 7. 内容 revision/hash pin 实现

- session 创建时把 6 道 check 的 `{revision, content_hash_full}` 整体写入 `content_manifest`。
- 判分使用 **session pin 的 answer_key**, 不使用当前内容文件。
- 每条 cp_response 冗余保存作答时的 revision/hash。
- 漂移测试(`test_content_drift_does_not_retroactively_apply`, fixture 模拟): session 开始后内容 revision 变化, 旧 session 仍按 pin 判分并标记 drift, **不悄悄切新版本**。

## 9. First-pass interruption 测试结果

| 场景 | 方法 | 结果 |
|---|---|---|
| A. 播放几秒后中断 | API 冒烟 + 单测 `test_interrupted_pass_invalid_and_restartable` | `cp_pass_interrupted` 记录, stage 回退 first_pass, `first_pass_valid=0`, round1 提交返回 409, 允许重新开始; 中断 pass 不产生任何 response 记录 |
| B. 播放一半退出页面再回来 | 同一代码路径(页面卸载发 interrupted / 心跳缺口 >9s 判无效) + session restore | 恢复后 stage=first_pass, valid=0, 必须重听; 实测会话 `cps_41e0e3acc721` 停留 first_pass、valid=0 |
| C. first pass 完成后再发 pass_start | API 冒烟 + 单测 | stage 不回退, `pass_attempt_count` 不再被刷成"第一次", round1 正常接受 |

实测会话 `cps_71a6724e6c3c`(中断恢复): `pass_attempt_count=3`, 事件含 `cp_pass_start×3 + cp_pass_interrupted×1`, 最终 `first_pass_valid=1` 完成全流程。
