### B. 播放中段离开页面再重新进入(Set2, 会话 cps_a4e93402eb83)

### C. first_pass 完整结束后刷新/离开再回来(Set1, 同会话)

- 操作: 重开后以锁定的 1.0x 完整播放(≈106s 实时)→ 自动进入 check_round_1 → 刷新页面。
- 页面证据: 刷新后仍为"整体理解检测"(check_round_1), **无"开始播放"按钮**, 不得重新获得新的 First Pass。
- DB 证据: `first_pass_valid=1, pass_attempt_count=2`(中断 1 次 + 完成 1 次), `cp_pass_start×2 / cp_pass_interrupted×1 / cp_pass_end×1`。

### 重要修复(验收过程中发现并已修)

**心跳/end 竞态 bug**: `_pass_valid` 原要求"最后一个 progress 心跳落在终点 2s 内", 但心跳间距为 4.5s —— 学生真实听完全程时, 末心跳与 end 事件之间天然可能有 2–4.5s 间隔, 导致**真实完成的 pass 被随机误判为无效**(Set2 pass1 实测: 末心跳 246213, end 248960, 差 2747ms, 曾判 invalid 并误显示"被中断")。

修复: end 事件本身作为"到达终点"的终末证据; 末心跳与 end 之间的缺口按一个心跳周期(9s)上限校验, 而非 2s。纯验收 bug 修复, 无新功能。

回归测试(新增 2 项):
- `test_end_event_counts_as_terminal_evidence` — 用 Set2 pass1 真实链形状, 判 valid + 进 check_round_1
- `test_end_event_far_after_last_heartbeat_still_invalid` — end 不能掩盖真正断档(缺口 19s → invalid)

**修复后浏览器复验**: Set2 会话第三次尝试以 1.0x 完整播放 → `first_pass_valid=1, stage=check_round_1`, 无误判"中断"提示。

## 补充项 2: First Pass 播放速度锁定

**区分**: 此前验收报告中的"提速"是 *test automation acceleration*(测试脚本经 evaluate 临时改 playbackRate 以缩短等待), 不是学生产品行为。本轮起连这条路也锁死:

- `RangePlayer.vue`: `startPlay` 与 `onMounted` 强制 `playbackRate = 1.0`; 新增 `@ratechange` 监听, 任何外部改速(控制台/插件)立即重置回 1.0。
- UI 无倍速控件: audio 无 `controls` 属性, 页面无 0.75/1.25/1.5/2x 任何入口。
- **浏览器实测**: 播放中经 evaluate 注入 `playbackRate = 1.5` → 300ms 内被 ratechange 处理器重置回 1.0(实测读回值: initial=1, set=1.5, after_lock=1)。
- 新增源码级断言测试 `PlaybackRateLockTest`(2 项): 无原生 controls/无倍速文案; 锁定代码存在。
- 本轮全部浏览器实测均在锁定后的 1.0x 下完成(Set1 完整遍 ≈106s 实时)。

## 补充项 3: V2.2 Release Gate 实际执行

`student_release_allowed = false` 不是纯 metadata, 默认(无环境变量)配置下:

- **入口**: 首页 Pilot 卡片区 `v-if="practiceMaterials.length"`; gate 关闭时 materials 返回空列表 → 入口不渲染。
- **端点**: 本轮补齐 events / round1 / round2 三个此前漏网的写端点 gate(bundle / audio / sessions / find / state 此前已有)。现在 9 个 V2.2 端点在 gate 关闭时全部 403 或空列表。
- **绕过测试**(新增 3 项 backend test):
  - `test_gate_closed` — materials/bundle/audio/create 全堵
  - `test_gate_closed_covers_session_endpoints` — find/state/events/round1/round2 全堵(无论 session 是否存在)
  - `test_existing_session_blocked_after_gate_closes` — gate 开着时创建的 session, gate 关闭后立即 403, 重新打开后数据不丢

`profile_eligible = false` 保持不变(每个 session_state 响应中硬编码返回)。
